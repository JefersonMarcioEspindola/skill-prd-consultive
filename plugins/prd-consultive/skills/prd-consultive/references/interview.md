# Question bank

Use these questions as raw material, not a form. Pick only what the idea hasn't answered yet, adapt the options to the context and skip the obvious. A good round has 2 to 4 questions, each with options and a recommendation when it makes sense. Ask them in the session's language.

**How to format a question:**

```markdown
**1. Who pays for the product?**
A) The user, with a monthly subscription *(recommended: simplest to validate)*
B) The company the user works for
C) Free for the user, revenue comes from elsewhere (ads, commission)
D) Other: ___
```

If there's a tool for clickable option questions, use the same structure in it.

**Order:** from what changes the product the most to what changes it the least. Audience and problem come before features; features come before stack.

---

## Block 1: Problem (phase 1)

- What problem does this solve, in one sentence, from the point of view of the person who suffers from it?
- How often does that person run into it? (every day / every week / now and then)
- What happens if they don't solve it? (lose money / lose time / get embarrassed / nothing serious)
- Do you have this problem, or know people who do? Roughly how many?

## Block 2: Audience (phase 1)

- Who's the first person who would use it? Be specific (not "small businesses", but "pet shop owners with 1 to 3 employees").
- Is the person who uses it the same person who pays?
- In what context would they use it? (at a work computer / on the phone, on the move / both)
- How comfortable are they with technology?

## Block 3: Solution and alternatives (phase 1)

- How does this person solve the problem today? (spreadsheet / WhatsApp or another messenger / paper / another app / they don't)
- What's bad about the current solution?
- What's the one thing the product has to do really well? If only one feature were left, which would it be?
- Why now? (a law changed / a technology appeared / you got access to this audience / another reason)

## Block 4: Business (phase 2 onward, Helena's area)

- Revenue model: (subscription / usage-based / commission / one-time sale / don't know yet)
- What price range do you have in mind, and based on what?
- How do the first customers arrive? (your network / content / partnership / ads / direct sales)
- What, in 90 days, would tell you it was worth it?

## Block 5: Scope and flows (phase 4, Caio's and Bia's areas)

- What does the user need to be able to do the first time they open the product?
- List the 3 to 5 things the MVP has to do. What would you remove if you had to launch in half the time?
- What types of users are there? (just one / admin and regular user / several roles)
- Does it need login? With what? (email and password / Google / magic link / phone)
- Is there an offline part, notifications, payments or integrations with other systems?

## Block 6: Data (phase 4, Caio's area)

- What are the main "things" in the system? (for example: client, workout, payment)
- Is any data sensitive? (health, financial, documents, minors)
- Does it need to import data from somewhere at the start? (spreadsheet, another system)
- How long is data kept, and can the user delete it?

## Block 7: Constraints (phase 4)

- When does the first version need to be live? (today / this week / this month). Remember that code comes out fast with an agent; what sets the date is usually third-party approvals and user testing.
- Who's building it? (you / a team / a freelancer / an AI agent with you reviewing)
- Monthly infrastructure budget? (close to zero / small / more than that). Use the user's currency.
- Is anything already decided that can't change? (stack, vendor, platform)

## For fast mode

A single round, only with what blocks. The questions that block most often:

1. Who the main user is (if the material doesn't say).
2. What's out of the MVP (it's almost never written down).
3. Stack, if there's no repository and no preference in the profile.
4. The metric that defines success.
