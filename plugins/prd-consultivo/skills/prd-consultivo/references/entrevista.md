# Banco de perguntas

Use estas perguntas como matéria-prima, não como formulário. Escolha só as que a ideia ainda não respondeu, adapte as opções ao contexto e pule o que for óbvio. Uma boa rodada tem de 2 a 4 perguntas, cada uma com opções e uma recomendação quando fizer sentido.

**Como formatar uma pergunta:**

```markdown
**1. Quem paga pelo produto?**
A) O próprio usuário, por assinatura mensal *(recomendo: mais simples de validar)*
B) A empresa onde o usuário trabalha
C) Gratuito para o usuário, receita vem de outro lado (anúncio, comissão)
D) Outra: ___
```

Se houver ferramenta de pergunta com opções clicáveis, use a mesma estrutura nela.

**Ordem:** do que mais muda o produto para o que menos muda. Público e problema vêm antes de funcionalidade; funcionalidade vem antes de stack.

---

## Bloco 1: Problema (fase 1)

- Qual problema isso resolve, em uma frase, do ponto de vista de quem sofre com ele?
- Com que frequência a pessoa passa por isso? (todo dia / toda semana / de vez em quando)
- O que acontece se ela não resolver? (perde dinheiro / perde tempo / passa vergonha / nada grave)
- Você tem esse problema, ou conhece quem tem? Quantas pessoas, mais ou menos?

## Bloco 2: Público (fase 1)

- Quem é a primeira pessoa que usaria? Seja específico (não "pequenas empresas", e sim "donos de pet shop com 1 a 3 funcionários").
- Quem usa é a mesma pessoa que paga?
- Em que contexto ela usaria? (no computador do trabalho / no celular, na rua / nos dois)
- Qual o nível de familiaridade dela com tecnologia?

## Bloco 3: Solução e alternativas (fase 1)

- Como essa pessoa resolve o problema hoje? (planilha / WhatsApp / papel / outro app / não resolve)
- O que é ruim na solução atual?
- Qual é a única coisa que o produto precisa fazer muito bem? Se só sobrasse uma funcionalidade, qual seria?
- Por que agora? (mudou uma lei / surgiu uma tecnologia / você ganhou acesso a esse público / outro motivo)

## Bloco 4: Negócio (fase 2 em diante, área da Helena)

- Modelo de receita: (assinatura / por uso / comissão / venda única / ainda não sei)
- Faixa de preço que você imagina, e com base em quê?
- Como chegam os primeiros clientes? (sua rede / conteúdo / parceria / anúncio / venda direta)
- O que te diria, em 90 dias, que valeu a pena?

## Bloco 5: Escopo e fluxos (fase 4, áreas do Caio e da Bia)

- O que o usuário precisa conseguir fazer na primeira vez que abre o produto?
- Liste as 3 a 5 coisas que o MVP precisa fazer. O que você tiraria se precisasse lançar na metade do tempo?
- Quais tipos de usuário existem? (só um / admin e usuário comum / várias funções)
- Precisa de login? Com quê? (e-mail e senha / Google / link mágico / telefone)
- Existe parte offline, notificações, pagamentos ou integrações com outros sistemas?

## Bloco 6: Dados (fase 4, área do Caio)

- Quais são as "coisas" principais do sistema? (por exemplo: aluno, treino, pagamento)
- Algum dado é sensível? (saúde, financeiro, documento, menores)
- Precisa importar dados de algum lugar no começo? (planilha, outro sistema)
- Quanto tempo os dados ficam guardados, e o usuário pode apagar?

## Bloco 7: Restrições (fase 4)

- Quando a primeira versão precisa estar no ar? (hoje / esta semana / este mês). Lembre que o código sai rápido com agente; o que define a data costuma ser aprovação de terceiros e teste com usuários.
- Quem vai construir? (você / time / freelancer / agente de IA com você revisando)
- Orçamento mensal de infraestrutura? (perto de zero / até R$ 200 / mais que isso)
- Existe algo já decidido que não pode mudar? (stack, fornecedor, plataforma)

## Para o modo rápido

Uma única rodada, só com o que bloqueia. As perguntas que mais costumam bloquear:

1. Quem é o usuário principal (se o material não diz).
2. O que fica fora do MVP (quase nunca está escrito).
3. Stack, se não houver repositório nem preferência no perfil.
4. A métrica que define sucesso.
